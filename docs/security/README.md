# セキュリティ要件と方針

SONOMAMAのセキュリティ要件は、人がこのディレクトリに書いて管理する。Harnessやアプリのコードにある設定は、ここに書いた要件を守らせるためのもので、要件そのものはここが基準になる。

現時点では方針の全文や業務上の権限はまだ決めていない。このディレクトリには、決めるべき項目と、それぞれをHarnessのどのルールで守らせるかを書いている。
誰が何を閲覧できるか、何を個人情報とするか、どれだけ保存するか、どの条件で匿名化するかは、プロダクトの担当者と人が設計判断として決める。AIが推測で決めることはしない。

## 安全性に関わる変更の扱い

認証・個人情報・データベース・インフラなど、安全性に関わる変更は、次のように扱う。

- 人はSBIの承認で、その変更を行うかを判断する（Human Gate）。承認済みSBIに対して、実装前の承認を重ねては求めない。承認済みSBIに書かれていない新しい影響が見つかったら、実装を止めて人の判断に戻す。
- 変更の種類ごとに決めた検証を必ず実行する。検証に失敗した場合や、検証がまだ用意されていない場合は、人が承認していても完了扱いにしない。
- 秘密情報の検査（secret-scan）と禁止パターンの検査（forbidden-pattern-check）は、リスクのレベルに関係なくすべての変更で行う。
- 影響が重いもの（認証、認可、行単位のアクセス制御、個人情報、権限の割り当て、秘密情報、本番インフラ、破壊的な操作、データの保存と削除、ログへの個人情報出力）は、リスクを最も高いレベル3とし、mergeに別々の2人以上の承認を必要とする。
- それ以外（通常のデータベースのマイグレーション、スキーマ、CI/CD、Harnessのセキュリティ設定、重要な設計の記録）は、リスクをレベル2として人1人の承認でmergeできる。内容に破壊的・不可逆な操作が含まれる場合は、そこでレベル3へ上がる。

変更の種類ごとの内容は、次の文書に分けて書いている。

| 文書 | 扱う変更 |
| --- | --- |
| [authorization.md](authorization.md) | 認証、認可、データベースの行単位のアクセス制御（RLS） |
| [pii.md](pii.md) | 個人情報、ログ、データの保存と削除 |
| [secrets.md](secrets.md) | パスワードやAPIキーなどの秘密情報 |
| [threat-model.md](threat-model.md) | データベースの変更、CI/CD、インフラ、破壊的な操作、重要な設計 |

このディレクトリの文書や、Harnessのセキュリティ設定そのものを変える場合も同じ扱いになる（ルールID: SEC-CONFIG-001）。

## Harnessの設定との対応

各ルールにはSEC-で始まるIDを付けている。Harnessは同じIDを使って、該当する変更を見つけ、必要な検証と承認を求める。
設定は.harness/rules/security.json（変更の見つけ方と必要な検証）と.harness/rules/human-gates.json（実装前の承認が要るルール）にある。
Harnessが確かめるのは、IDと文書の対応が取れているかどうかだけで、要件の中身が妥当かどうかは人がレビューする。

## 変更内容の検査（ローカルのrunとCI）

秘密情報・禁止パターン・ログへの個人情報出力の検査（secret-scan、forbidden-pattern-check、pii-log-check）は、ローカルのrunとCIの両方で行う。検査する範囲は次のとおり異なる。

| 実行場所 | 検査するファイルと内容 | 検査対象が0件のとき |
| --- | --- | --- |
| ローカルのrun（harness:run） | run worktreeのbaselineからコミットまでの差分にあるファイル（削除とSBI Issueのsnapshotを除く）と、SBIがファイル名で許可したファイル。どちらも全文を読む | SKIPとし、Securityは不合格になる |
| CI（harness:judge --base） | PRの差分にあるファイル（削除を除く）の追加行 | PASSのまま |
| CI（harness:judge --all、mainへのpush） | 差分がないため検査しない | PASSのまま |

SBI Issueから作ったSBIはディレクトリ単位で範囲を許可し、ファイル名では何も許可しない。そのため、ローカルのrunは許可範囲ではなく実際の差分を検査する。
SBI Issueのsnapshot（.harness/state/sbi-<N>.json）はHarnessがIssue本文から書くもので、Agentが書いたコードではないため、ローカルのrunでは検査対象に数えない。CIはPRの差分として検査する。
CIで検査対象が0件のときの扱い（削除だけのPR、mainへのpush）と、ローカルのrunで削除だけの変更が検査対象0件のためSKIPとなる扱いは、#184 で決める。
