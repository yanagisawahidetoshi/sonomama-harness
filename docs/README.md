# docs

人が読むための設計資料を置く。システムの全体像、設計の考え方と理由、ADR、セキュリティ要件、運用の概要がここにある。

| ディレクトリ | 内容 |
| --- | --- |
| [architecture/](architecture/README.md) | システムの構成と、機能ごとの設計を書くテンプレート |
| [security/](security/README.md) | セキュリティ要件と、Harnessで守らせるルールとの対応 |
| [product/](product/sbi-template.md) | プロダクトの要件と作業単位（SBI）のテンプレート |
| [adr/](adr/README.md) | 設計上の判断の記録（ADR）。状態の意味とテンプレート |
| [workflows/](workflows/README.md) | 開発の流れの概要と、API仕様を見る・試す手順 |

## 文書の置き場所の分け方

このリポジトリでは、読み手ごとに文書の置き場所を分けている。

| 場所 | 読み手 | 置くもの |
| --- | --- | --- |
| docs/ | 人 | 判断の背景、設計の意図、要件 |
| .ai/ | AI | 実装するときに守る短い制約と作業手順 |
| .harness/ | Harness | 機械が実行・検証・強制する設定とルール |

同じ内容を複数の場所にコピーしない。docs/の文書は、前提知識がなくても読める日本語で書く。Harness内部の状態名や実装の詳細は.ai/と.harness/に置く。
